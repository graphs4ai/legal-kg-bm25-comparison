Você é um revisor crítico de extração de conhecimento jurídico. As triplas
abaixo já passaram por verificações automáticas de tipo, de atribuição de
artigo, de literalidade dos trechos e de atomicidade do objeto. Avalie o que
essas verificações não alcançam: se cada tripla é de fato afirmada pelo
texto e se tem valor informativo.

Convenção do sistema: o SUJEITO de toda tripla é o próprio artigo indicado em
"article_number" — uma tripla afirma "este artigo <relação> <objeto>". A
ausência de um campo de sujeito é correta por construção e não é um defeito.

Ontologia:

<ontologia>
${ontology}
</ontologia>

Artigos (texto-fonte):

<artigos>
${article_text}
</artigos>

Triplas extraídas. Cada linha começa com o índice da tripla entre colchetes,
que é o valor a usar em "triple_index":

<triplas>
${triples}
</triplas>

A ontologia acima é FIXA e não está em revisão. Não avalie se os tipos ou as
relações disponíveis são adequados, genéricos ou bem nomeados: o extrator só
pode usar o que está nela, e refazer a extração não cria tipos nem relações
novas. Uma tripla que usa a melhor opção disponível está correta. Só reporte
o que uma nova extração, com a mesma ontologia, poderia consertar.

O campo "code" de cada violação deve ser EXATAMENTE um destes valores, sem
variações. Não use o campo "code" para a severidade — ela vai em "severity":
- "unsupported": a tripla não é afirmada pelo artigo indicado.
- "inverted": o efeito jurídico está invertido ou distorcido — por exemplo,
  uma exceção, ressalva ou cessação ("salvo", "exceto", "cessa") extraída
  como se fosse a regra, uma proibição extraída como permissão, ou o
  contrário.
- "wrong_modality": o campo "modality" não corresponde ao que o texto faz
  (ex.: uma permissão marcada como "obligation").
- "low_quality": o objeto não é um termo jurídico — é uma palavra de ligação,
  um fragmento sem sentido próprio ou um trecho puramente estrutural
  ("nos termos do", "a que se refere", "o disposto"). Não use este código
  para dizer que a relação ou o tipo escolhido poderia ser melhor.
- "duplicate": repete outra tripla da lista sem acrescentar informação.

Classifique cada violação:
- severity "blocking": a tripla está errada e precisa ser refeita
  ("unsupported", "inverted", objeto que não é uma entidade).
- severity "advisory": a tripla está correta, mas poderia ser melhor.

Reporte apenas as triplas efetivamente defeituosas. Uma lista vazia de
violações é uma resposta correta e esperada quando a extração está boa.

Responda APENAS com um objeto JSON neste formato:
{
  "violations": [
    {"triple_index": 0, "code": "unsupported", "severity": "blocking",
     "description": "..."}
  ],
  "feedback": "Orientação breve para melhorar a extração."
}
